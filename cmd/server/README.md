# cmd/server

Точка входа сервера сбора метрик.

## Аудит запросов

Аудит включается независимо для каждого приёмника:

- `--audit-file` / `AUDIT_FILE` — путь к файлу JSONL; новые события дописываются в конец.
- `--audit-url` / `AUDIT_URL` — полный HTTP(S) URL; каждое событие отправляется отдельным POST с `Content-Type: application/json`.

По умолчанию оба приёмника отключены. Непустые переменные окружения имеют приоритет над флагами, как и остальные настройки сервера.

```sh
go run ./cmd/server --audit-file audit.jsonl --audit-url http://localhost:9000/audit
```

После успешного обновления через `/update/{type}/{name}/{value}`, `/update[/]` или `/updates/` сервер публикует одно событие всем подключённым наблюдателям:

```json
{"ts":1793000000,"metrics":["Alloc","PollCount"],"ip_address":"127.0.0.1"}
```

`ts` — Unix-время в секундах; `metrics` — имена в порядке входного запроса; `ip_address` — адрес соединения без порта. Заголовки прокси не используются. Чтение метрик и неуспешные обновления событий не создают. При синхронном сохранении событие публикуется после успешной записи метрик на диск.

Доставка выполняется до ответа клиенту. Таймаут HTTP-приёмника — 2 секунды; перенаправления не выполняются. Ошибка доставки логируется и не меняет успешный ответ обновления, не мешает другим наблюдателям и последующим запросам. Повторной отправки и очереди нет. Некорректный URL или невозможность открыть настроенный файл приводят к ошибке запуска сервера.
